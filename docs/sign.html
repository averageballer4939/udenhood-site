Your coin

Sign your repo

One small file tells everyone which wallet speaks for the repo, and which coin it launches. You commit it yourself.

Open Launch, paste your repo, log in, then press Sign on GitHub: GitHub opens with the file ready to commit.

The file

{
  "udenhood": 1,
  "chain": 4663,
  "wallet": "0x52908400098527886E0F7030069857D2E4169EE7",
  "ticker": "COIN",
  "coin": "0x8617E340B3D01FA5F11F306F4090FD50E238070D"
}
FieldWhat it isValue
udenhoodversion of this format1
chainchain id of Robinhood Chain4663
walletthe wallet that launches the coin0x and 40 hex characters
tickerthe ticker of the coin2 to 10 letters or digits, in capitals
cointhe address the coin will have0x and 40 hex characters

An address before the coin exists? Pons derives a coin's address from the wallet that launches it and from the coin's own details: name, ticker, image, text, links, creator tax. Udenhood replays the launch on the chain, without sending it, and reads the address. You write nothing by hand.

Add it

  1. Paste your repo

    Step 1 of the page, as owner/repo. The line under the title answers “Found.” once GitHub knows the repo.

  2. Check the coin

    Step 2. Settle the name, the ticker, the text and the image now: they decide the address the file names.

  3. Log in

    Step 3, Log in. The file names the wallet you are logged in with: you do not type it. How to log in.

  4. Press Sign on GitHub

    GitHub opens in a small window on its new file page, on your default branch, with the name and the content already filled in.

  5. Commit on GitHub

    Read the file, then commit it. You need write access to the repo.

  6. Wait a few seconds

    The page reads the repo again by itself. The line turns gold, “Signed: the repo names your wallet and $COIN.”, and the button reads Signed.

Root of the default branch. A file on another branch, or inside a folder, is not read.

Window blocked, or nothing happens? Open See the file: Copy the file copies the content, to create udenhood.json by hand at the root of your default branch. Check again reads the repo at once.

Change the coin after signing

The file names one exact coin. Change its name, ticker, text, image, links or creator tax, and its address changes: the line reads “The coin changed since you signed. Update the file.” Your first buy does not change the address.

A last check runs when you press Launch the coin. If the coin about to be created is not the one the file names, nothing is sent and the page says “The coin address changed since you signed. Sign your repo again.”

Remove it

Delete udenhood.json from the default branch and commit. The next check reads “No proof file yet.” GitHub's raw file server can keep the old version for a few minutes.

What signing does not do

  • Nothing on-chain. No transaction is sent and nothing is spent. The coin is created when you press Launch the coin, by your own wallet.
  • No access for us. The page asks for no key and no GitHub login. It only opens a GitHub link.
